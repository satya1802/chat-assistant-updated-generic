<!-- sdlc:auto:start overview -->
Chat Assistant - Updated Generic is a two-part scaffold generated by the Quorq AI SDLC platform for a full-stack AI chatbot: a React 19 + TypeScript SPA (Vite, Tailwind CSS v4, react-router) containing the approved, reviewed screens, and a FastAPI 0.115 backend that currently exposes only a `/health` endpoint. The frontend renders seeded sample data and is not yet wired to the backend; the backend has no data model or routers beyond its health check, uses SQLAlchemy with a SQLite file by default (swappable via `DATABASE_URL`, with PostgreSQL/pgvector planned per the product spec), and creates its schema on startup rather than via migrations.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for npm, Vite 6, React 19 toolchain)
- Python 3.12
- pip
- Docker and Docker Compose (optional, for the PostgreSQL service in docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. cd backend && pip install -r requirements.txt
3. (optional) docker compose up -d db  # starts PostgreSQL 16 defined in docker-compose.yml
4. (optional) set DATABASE_URL to point at Postgres; otherwise the backend defaults to a local sqlite:///./app.db file
5. cd frontend && npm install
6. (optional) set VITE_API_BASE_URL if the backend is not at http://localhost:8000
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one router per architecture component, one route per spec endpoint; unimplemented routes return a typed StubResponse rather than raising
- Backend models use a shared SQLAlchemy DeclarativeBase (app.database.Base); main.py imports models before calling create_all
- Backend config via environment variables: DATABASE_URL (defaults to local SQLite), ALLOWED_ORIGINS (comma-separated CORS origins, defaults to the Vite dev server)
- Frontend: one screen component per approved screen under src/screens, routed from a single table in App.tsx
- Frontend shared vocabulary lives in src/lib/ui.tsx and src/lib/icons.tsx; brand tokens in src/lib/brand.ts and index.css as CSS variables
- Frontend API access centralized in src/lib/api.ts (apiFetch helper, VITE_API_BASE_URL); screens do not yet call it and instead use seeded sample data
- Component tests (Vitest) live beside the code they cover and are scoped to src/**/*.{test,spec}.{ts,tsx}; Playwright specs live separately in e2e/
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend requests to the backend are blocked by CORS | Set ALLOWED_ORIGINS on the backend to include the frontend's origin, or run the frontend at http://localhost:5173 (allowed by default) |
| `pytest` fails with ModuleNotFoundError: app | Run pytest from the backend/ directory so pytest.ini's pythonpath = . applies |
| `npm run test:e2e` fails because no browser is installed | Run `npm run test:e2e:install` once to fetch Chromium before running the e2e suite |
| Backend data doesn't persist as expected / wrong database used | Check the DATABASE_URL env var; the backend defaults to sqlite:///./app.db locally, not the PostgreSQL container from docker-compose.yml |
| `npm run build` succeeds but the app has type errors | Run `npm run typecheck` (tsc --noEmit) separately, since build does not typecheck |
